## 1. 登录、回调端口与本机凭据收编

| 现象 | 原因分析 | 解决方法 |
| --- | --- | --- |
| **Linux 服务器登录成功但报凭据无法安全保存**（`credentials could not be saved securely`） | 默认 `poolStorage: keyring` 依赖桌面 Secret Service（`libsecret` / `secret-tool`），无头服务器通常未安装或未解锁钥匙环 | 在 **设置 → 订阅服务 → ChatGPT → 账号存储位置** 切换为 **DSH 凭据库（`credentials`）**，或在 `cordis.patch.yml` 中配置 `poolStorage: credentials` 后重载插件 |
| **ChatGPT 登录报 `1455` 端口被占用** | 旧登录回调或本机其它进程占用了 `localhost:1455` | 点击「取消登录」或结束占用 `1455` 端口的进程后重试；无本地浏览器或端口受限时直接改用卡片上的 **设备码登录** |
| **Command Code 浏览器登录失败** | `127.0.0.1:5959–5968` 端口全部被占用，或跨次点击导致 `state` 不匹配 | 释放端口并重新发起一次登录；无浏览器环境可在 Command Code Studio 创建 API Key 后粘贴登录 |
| **Claude 手动粘贴授权码提示「请把 `#` 后面的部分一起复制」** | 手动模式必须校验完整 `<授权码>#<state>` 以防登录 CSRF，只粘前半段会被拒绝 | 将浏览器授权结果页显示的整段 `<code#state>`（或完整重定向 URL）原样粘贴 |
| **提示「从 Codex CLI / Claude Code 导入的登录已过期」** | 导入的是**只读快照**，插件刻意永不刷新它（跨进程抢刷单次轮换令牌会把你踢出官方 CLI） | 回到终端运行官方 `codex` 或 `claude` 完成重新登录，再回设置页点一次「导入 / 收编」即可原地更新 |
| **Kimi Code 点击「重新登录」时被取消并提示账号不一致** | 浏览器当前登录的 Kimi 账号与你在号池该行点击重登的账号不是同一个 | 切换到对应 Kimi 账号后再点该行的「重新登录」，或直接点顶部的「添加账号」作为新账号入池 |
| **Windows DPAPI 解密失败 / Linux 凭据文件不可用** | Windows 换了系统运行用户；或 Linux 上凭据文件非当前用户所有、权限非 `0600`（父目录非 `0700`） | 确认以同一操作系统用户运行 DSH；Linux 上修正目录 `0700` 与文件 `0600` 权限，或在设置页注销后重新登录 |

## 2. 模型选择器与路由冲突

| 现象 | 原因分析 | 解决方法 |
| --- | --- | --- |
| **设置卡提示「模型路由已被其他 Provider 占用」** | DSH 中已有另一个插件或内置 `llm-pi-ai` 配置注册了同名 Provider ID（如 `command-code`、`cline-pass`） | 从另一个插件/内置模型配置中移除同名 Provider，本插件会在下一次路由变更事件时自动接管，无需重启 DSH |
| **某条线路的模型完全不出现在对话页模型选择器中** | ① 该线路右上角「启用此供应商」总开关处于关闭；② 未登录任何有效账号；③「可用模型」列表未勾选 | 打开对应线路标签页，开启总开关、确认至少一个账号就绪，并在模型列表中勾选所需模型 |
| **上游刚发布的新模型未显示** | 本地使用了持久化的目录快照，或当前套餐/工作区无权访问该模型 | 在对应线路设置页点击 **刷新模型目录（强制刷新）**；若仍不出现，说明上游实时目录未对该账号开放该模型（注：`minimax-code` 因网关未开放 `/v1/models` 使用随包固定目录，需升级插件获取新模型） |
| **Claude 报 `claude_code_version_too_old`** | 上游对新模型（如 Opus 5.5 要求 `>= 2.1.280`）校验客户端申报版本 | 升级本插件至最新版，或临时设置环境变量 `DSH_CLAUDE_CLI_VERSION` 抬高申报版本号（此错误不会将账号标为失效） |

## 3. 请求失败、限流冷却与流式超时

| 现象 | 原因分析 | 解决方法 |
| --- | --- | --- |
| **偶发 `502 / 503 / Upstream model provider is temporarily unavailable`** | 上游模型供应商瞬时过载或网关抖动，与账号凭据无关 | 插件已内置有界指数退避自动重试（最多 3 次）；若持续失败可临时切换同线路下的其它模型 |
| **返回 `429` 但有的会自动换号、有的只原地退避重试** | 插件区分**账号级配额耗尽**（进入窗口冷却并自动切到号池下一个账号）与**全局引擎瞬时过载**（如 `engine is currently overloaded`，所有账号共享同一瓶颈，换号只会把号池抽干，因此原地退避重试） | 若所有账号均进入配额冷却，可在设置页或看板卡片查看最早重置倒计时，或补充新账号入池 |
| **Kimi Code 报 `401 does not have access to k3` 或上下文受限** | 属于套餐档位权限限制而非登录失效（例如 `k3` 1M 窗口需 Allegretto 及以上，Moderato 上限 256K） | 换用 `kimi-for-coding` / `k3-256k`，或将该模型的「上下文窗口覆盖」调整为 `256K` |
| **WorkBuddy 提示号池已暂停 30 分钟（`WORKBUDDY_POOL_PAUSED`）** | 上游返回 `11140` 账号受限，且 30 分钟内已有 2 个不同账号触发该风控，号池启动保护性熔断 | 等待 30 分钟自动解除整池暂停；被标记 `11140` 的受限账号需人工核查并重新登录后才会回到轮换 |
| **Cline Pass 报 `client-supplied "providerOptions" model routing is not supported`** | 旧版客户端钉选字段不被 Cline 接受 | 升级到已移除上游钉选的版本；请求由网关自动路由，卡片只读回实际渠道 |
| **MiniMax Code 额度面板提示需要官方客户端标识头** | 插件默认不伪造 MiniMax 第一方客户端签名头，因此用量接口拒绝读取（完全不影响模型对话） | 可直接在 MiniMax 官方控制台查看用量条；若接受携带第一方标识头的取舍，可设置 `DSH_MINIMAX_CODE_QUOTA_ATTRIBUTION=1` 重启 DSH |
| **长请求约 2 分钟无输出后自动报错重试** | 流式空闲看门狗（chunk 之间默认 120s，Ollama 为 300s）检测到超过预算仍零字节到达，主动切断僵死连接触发重试 | 属于防挂死保护机制；Codex 线路用 `codexStreamIdleTimeoutMs` 调整，其它线路按共享值 |

## 4. 上下文超限、压缩失败与多模态体积

| 现象 | 原因分析 | 解决方法 |
| --- | --- | --- |
| **长对话触发自动压缩重试，或手动压缩失败** | 输入或「输入 + 输出预留」触及模型上下文窗口，或 Kimi 请求序列化体积触及本档字节上限（1M 档 24 MiB / 256K 档 2 MiB） | ① 确认当前 Preset 启用了压缩后端；② 可在「设置 → 订阅服务 → ChatGPT → 压缩模型」指定一个大窗口/高速模型专门负责写摘要；③ Kimi 中英高密度长会话可设 `DSH_KIMI_CODE_BYTES_PER_TOKEN=8`（中文取 `12`）让宿主在撞墙前提前压缩 |
| **回答在中途停止并显示 `max-tokens`** | 触发了上游模型单次最大输出上限（注：`codex-chatgpt` 因上游拒收 `max_output_tokens` 参数，输出上限完全由服务端决定） | 让模型继续未完成的部分，或拆分单次生成任务粒度 |
| **历史早期的截图被模型告知已省略** | 单次请求内联图片超过线路预算（Codex 2 MiB、Claude 8 MiB、Command Code 12 MiB、MiniMax 16 MiB、Kimi 粘性 20 MiB 高水位）时，按**最旧优先**替换为可见说明文本以防整轮请求体积超限失败 | 需要模型重新查看某张早期图片时，在当前轮次重新读取或附上该图即可；Codex / Kimi / MiniMax 支持通过对应 `DSH_*_MAX_IMAGE_BYTES` 环境变量调整预算 |
| **Kimi / MiniMax 发送视频被降级为文字说明** | 当前所选模型不支持视频（如 `k3-256k`、`MiniMax-M2.7`）、容器格式不在白名单内，或 Kimi 当前走了无视频块规范的 Anthropic 协议分支 | Kimi 切换至 `k3` / `k3.1-pro` / `kimi-for-coding`（OpenAI 协议）；MiniMax 切换至 `MiniMax-M3` / `MiniMax-M3.1-Flash`，并使用标准 `.mp4` / `.mov` / `.webm` 容器 |

## 5. 网络代理与 `web_fetch` 抓取异常

| 现象 | 原因分析 | 解决方法 |
| --- | --- | --- |
| **`web_fetch` 报错 `WEB_BLOCKED_URL` / `resolves to a non-public IP address`** | 本机开启了 Clash / Mihomo 等 `fake-ip`（`198.18.0.0/15`）代理，但插件处于「直连」或未检出代理，导致 DSH 内置抓取器在本地 DNS 校验阶段拦截了 fake-ip | 打开 **设置 → 订阅服务 → ChatGPT → 网络代理**，选择 **系统代理（自动检测）** 或填入自定义本地代理地址（如 `http://127.0.0.1:7890`），在默认 `fetchProvider: auto` 下插件会自动接管 `web_fetch` 并交由代理解析域名 |
| **本机跑了本地网关（`127.0.0.1`）担心被代理劫持** | 无需担心 | 回环地址（`127.0.0.0/8`、`::1`、`localhost`）与 `NO_PROXY` 列表始终绕过代理直连 |
| **Cline Pass / Ollama / Google OAuth 反复连接握手超时** | 终端环境变量未注入 GUI 进程，且系统代理未开启 | 在设置页配置显式自定义代理，或在 `$DSH_HOME/.env` 中写入 `HTTPS_PROXY=http://127.0.0.1:<端口>` |

## 6. 子代理授权与调度模式（`dispatch`）

| 现象 | 原因分析 | 解决方法 |
| --- | --- | --- |
| **调用 `subagent` 被拒，提示必须成对提供 `provider` 与 `model`** | 会话记录了子代理模型允许列表，本插件的 `subagentModelAuthorization` 守卫禁止省略参数静默继承主模型 | 让 Agent 先调用一次 `list_subagent_models` 获取当前会话已授权的 `{ provider, model }` 清单并显式传参；或在 DSH **Plugins → 子智能体** 设置卡中勾选需要授权的模型 |
| **调用 `subagent_fork` 被拒** | `subagent_fork` 强制继承当前父会话路由，而当前主代理所用的模型既不在子代理白名单内、也未开启允许父路由 Fork 自继承 | 在 **Plugins → 子智能体** 设置卡中开启「允许 `subagent_fork` 继承主模型」（全局或针对当前主模型），或将当前主模型勾选进白名单，或改用显式指定白名单内模型的 `subagent` |
| **在 0.2.1-rc.2 之前的 harness 上用 `dispatch` 预设，派出去的子代理联系不上** | 旧代 Agent Teams 运行时会注册 `spawn_teammate` 并用 team 作用域顶替 `send_message` / `list_agents` / `interrupt_agent`；该代已被 harness 移除，调度模式自 0.2.1-rc.2 起不再按代检测（原 `R0.5` 闸门已删除），因此对更早的 harness 不做兼容承诺 | 把 harness 升级到 ≥ 0.2.1-rc.2；或改用不带子代理编排的会话由主代理直接执行 |
| **`dispatch` 会话里子代理调用 `ask_user_question` / `enter_plan_mode` 或执行纯 `sleep` 被拦截** | `dispatchExecutionGuard`（默认开启）在执行期保护编排纪律：主控工具只归主代理，等待子代理应结束本轮靠通知唤醒而非 `sleep` 空转 | 属正常护栏行为；子代理应按拒绝提示将未决问题通过报告带回主代理处理 |
