## 2. Old-generation declaration gaps fixed during verification (type-only)

The isolated `0.1.5-rc.1` build exposed declaration gaps introduced by newer features; these were not `rc.3` behavioral changes.

- `src/index.ts`: Cordis 4.0.2 does not export `Volatile`. The runtime Config now uses a local structural `Volatile<T>` with `get(): T` for its boolean/number/string-literal fields. Current Cordis references remain structurally assignable.
- `src/client/minimax-code/commands-contract.ts`: old command declarations lack `SelectOptionGroup`, `CommandContribution.label`, and `icon`. The existing type-only boundary now supplies those additive shapes locally while intersecting with the Harness contribution, so both old and current registries receive the same object.
- `src/client/progress-updates/settings-binding.ts` and `settings-section.tsx`: old `dsh-client-ui-settings` has no `ConfigForm` exports. The snapshot and the three form methods used by this card are declared structurally at the existing duck-typed service boundary. Old deployments still render the no-service fallback; current deployments still call the real `configForms` service.

There is no new runtime version check, request-wire change, or change to the command/form objects. The current-generation focused tests (82 cases) and all three full verification generations cover the result.

## 6. Follow-up: standalone `list-agents` removal (fatal at session creation; bridged)

- A user report showed `agent-preset/invalid: tool-subagent-list-agents (@deepseek-ai/dsh-tool-subagent-control/list-agents): never started` when creating a session with the default `dispatch` preset.
- Harness commit `4df09d37d50` (`refactor(subagent): register shared control tools together`) removes the `./list-agents` export and calls `registerListAgents(ctx)` plus `registerListSubagentModels(ctx)` from the main control entry. Built-in presets delete both standalone rows; this plugin's preset carries only the `list-agents` row.
- `src/host/agent-preset.ts` now resolves that row conditionally in `resolveDispatchPreset`: an installation with the old export keeps `DISPATCH_PRESET` byte-for-byte, while one without it drops only `tool-subagent-list-agents`. The main control row and every other delegation row are unchanged.
- `src/host/preset-sync.ts` now checks exact `exports` keys for subpath fallback probes. The old package-root-only fallback could report the removed subpath as present merely because the package was installed.
- Two regression cases pin this behavior: subpath-export detection and preserving/removing the row. Both failed before the fix and pass after it. The two preset suites total **69/69**, and all three TypeScript projects plus `npm run build` pass.
- A real local `0.2.1-rc.3-22ddee3` smoke with the linked plugin selected `调度模式` and created a new dispatch session through the Web button. Session files increased from 4 to 5, with zero `agent-preset/invalid` or `never started` matches.
- The first follow-up full run was **4649 passed / 8 skipped / 2 failed** (4659 total), with both failures confined to `test/claude-model-catalog.test.ts` after the Harness moved its reference artifact to `pi-ai@1.3.0`. The separate evidence review below resolved those failures; no failure was deleted or hidden.
