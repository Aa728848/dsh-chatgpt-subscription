## 2. Old-generation declaration gaps fixed during verification (type-only)

The isolated `0.1.5-rc.1` build exposed declaration gaps introduced by newer features; these were not `rc.3` behavioral changes.

- `src/index.ts`: Cordis 4.0.2 does not export `Volatile`. The runtime Config now uses a local structural `Volatile<T>` with `get(): T` for its boolean/number/string-literal fields. Current Cordis references remain structurally assignable.
- `src/client/minimax-code/commands-contract.ts`: old command declarations lack `SelectOptionGroup`, `CommandContribution.label`, and `icon`. The existing type-only boundary now supplies those additive shapes locally while intersecting with the Harness contribution, so both old and current registries receive the same object.
- `src/client/progress-updates/settings-binding.ts` and `settings-section.tsx`: old `dsh-client-ui-settings` has no `ConfigForm` exports. The snapshot and the three form methods used by this card are declared structurally at the existing duck-typed service boundary. Old deployments still render the no-service fallback; current deployments still call the real `configForms` service.

There is no new runtime version check, request-wire change, or change to the command/form objects. The current-generation focused tests (82 cases) and all three full verification generations cover the result.

## 3. Dependency closure evidence and traps

- Moving the root baseline reproduced the documented `dsh-attachment@0.2.1-rc.3 -> dsh-brand@0.2.1-rc.3` exact-peer `ERESOLVE`. Removing only `package-lock.json` was insufficient because the existing `node_modules` still contained rc.1. A clean lock was generated in a temporary manifest directory with neither the old lock nor old modules, then standard `npm ci` installed it. No `--force` or `--legacy-peer-deps` was used.
- The `0.2.1-rc.2` room pins every direct DSH dependency exactly to rc.2 and keeps the dev/peer invariant.
- The `0.1.5-rc.1` room pins all 31 reachable DSH packages exactly through `overrides`, computed recursively from npm's rc.1 package metadata. This prevents caret sibling ranges from silently selecting rc.3 (`dsh-agent` and `dsh-system-prompt` were two concrete examples). Its vendor closure is `cordis@4.0.2` plus `cordis-plugin-loader@1.0.3`; npm completes with full peer checking and no override flag.
- A clean room must be outside the repository. A room initially placed under `.build/` resolved the missing old-generation `@deepseek-ai/dsh-ptc-runtime` from the repository root's rc.3 `node_modules`, producing four misleading PTC failures instead of the expected module-not-found. Moving the same rooms to `/tmp` removed that fallback; only the `/tmp` results below are evidence.
