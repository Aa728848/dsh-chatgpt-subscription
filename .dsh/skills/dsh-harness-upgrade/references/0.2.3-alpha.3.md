## 2. 上游变更与兼容桥接（Upstream Delta & Bridges）

1. **工具执行器重构为可组合根注册表（PR #8882，`tool-registry-roots` — 启动/编译破坏性变更）**：
   - 上游将 `@deepseek-ai/dsh-tool-executor-{native,ptc}` 重命名为 `@deepseek-ai/dsh-tool-registry-{native,ptc}`，移除 `ctx.tools.setExecutor()` / `register(tool, { when })` / `definitions()` / `executable()` / `resolve()`，改为 `ctx.tools.setRoot(registry)`、`ctx.tools.include(source)`、`ToolStep` 声明锁定，以及 `ToolExecutionPipeline` + `executeToolBatch`（`@deepseek-ai/dsh-tools/pipeline`）；根注册表在 `get`/`getAll`/`include` 期间严禁回读 `ctx.tools`。
   - `src/entries/codemode.ts` 与 `src/host/runtime/codemode/{executor,transport}.ts`：移除顶层静态 `@deepseek-ai/dsh-tool-executor-native` 导入，新增 `createCodemodeRootRegistry` 供 `setRoot` 挂载（直接基于 `include(registrations)` 收到的底层源查询作用域归属、零回读 `ctx.tools`、按 `ToolStep` 锁定程序内绑定、通过外部动态加载的 `@deepseek-ai/dsh-tools/pipeline` 执行程序内子调用，并独立注册 `tools:sdk` 系统段）；同时保留旧代 `setExecutor` 同步动态加载路径。
   - `src/host/runtime/presets/agent-preset.ts` 与 `presets/dispatch/agent.cordis.yml`：新增 `NATIVE_REGISTRY_PACKAGE` 与 `PTC_REGISTRY_PACKAGE`，`resolveDispatchPreset` 放行新旧任一原生包，缺失时依次降级至 `tool-registry-ptc` → `tool-executor-ptc` → `tool-presentation`。
   - `src/entries/plan-mode-pipeline.ts`：存在 `tools.include` 时通过动态 `ToolSource` 随 `planModePipeline` 开关实时显隐 `enter_plan_mode` / `leave_plan_mode`，旧代继续使用 `tools.register(def, { when })`。
   - `src/host/runtime/guards/plan-mode-cache-guard.ts`：新增对 `tools.include` 的原型包装，拦截官方 `plan-mode` 的 `AgentToolRegistry`（包含 `exit_plan_mode`）使其对任意 scope 恒定可见，旧代保留 `tools.register` `{ when }` 剥离。
   - `src/host/runtime/guards/ptc-sdk-cache-guard.ts`：订阅 `tools/change` 维护 `registryEpoch`，在无 `definitions()` 时作为 `tools:sdk` 缓存指纹兜底。
   - `src/host/runtime/guards/timeline-cache-guard.ts`：无 `definitions()` 时回退包装 `tools.getAll()` 冻结 `timeline_tasks` 描述并消除假警告。
   - `src/host/runtime/guards/subagent-model-authorization.ts`：`routeParameterProbe` 在无 `definitions()` 时回退通过 `tools.get(toolName, agent)` / `tools.getAll(agent)` 探测工具参数。
2. **React 19 客户端升级与 Client 动态插件包（PR #9217 & #9451）**：
   - `src/client/` 对 `@deepseek-ai/dsh-client-ui-slots` 均为 type-only import 与模块扩展（新旧包根声明一致，保留根导入确保 `0.2.2-rc.5` / `0.1.5-rc.1` 洁净室编译通过），全量客户端代码与 UI 测试在 React 19.3.1 与 React 18.3.1 双代均零错误通过。
3. **子智能体默认模型（PR #9373）与路由事件迁移（PR #9006）**：
   - `src/client/features/subagent/{subagent-card-controller,SubagentCard,locales,styles}.ts(x)`：为遮蔽后的插件页「子智能体」卡片补齐 `defaultModel` 下拉选择、草稿态、禁用选模型开关下的独立保存及仅脏写 `set`/`unset`（兼容旧版宿主）。
   - `src/host/runtime/guards/subagent-route-audit.ts`：`childRoutesOf` 在 `subagent/descriptor` 不再记录 `agentProvider`/`agentModel` 时，回退读取子会话最新的 `model/selection` 事件及 `requestHeader()`。
4. **LLM `INVALID_TOOL_ARGUMENTS` 默认重试码、`agent/pre-step` 切模型压缩与上下文提醒（PR #3221 & #9040）**：
   - 16 条 LLM provider 线路的 `retryableCodes` 统一补充 `'INVALID_TOOL_ARGUMENTS'`，与上游 `DEFAULT_RETRYABLE_CODES` 对齐。
   - `src/host/runtime/guards/compaction-policy-guard.ts`：`observeFrom` 补充读取 `agent/pre-step` 载荷中的 `modelSelection`。
   - `src/host/runtime/cache-warmup/retrieval-intent.ts`：按 `source.form`（`snapshot` / `notice`）与 `source.kind` 优先跳过 `todo/reminder`、`time-context` 等合成消息，避免覆盖真实用户导航意图。
