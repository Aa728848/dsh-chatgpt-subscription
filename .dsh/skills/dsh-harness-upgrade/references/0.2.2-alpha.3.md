Previous plugin baseline: **0.2.1-rc.3**. Target: **0.2.2-alpha.3** (npm `alpha`; dist-tags at the time: latest `0.2.1-rc.5`, next `0.2.1-rc.5`, alpha `0.2.2-alpha.3`). The local `dsh --version` is also `0.2.2-alpha.3`.

Harness evidence was read from `C:\Users\A\Documents\deepseek-harness` across `dsh-v0.2.1-rc.3..dsh-v0.2.2-alpha.3`; the target tag is commit `05b1cae8db6e674c5685101494d4eec24652424a`. `dsh-v0.2.1-rc.5` is an ancestor of the alpha.3 tag, so the target includes the current latest/next fixes.

## 1. Standalone tool executors and PTC batches (behavioural; bridged)

- `packages/core/tools/src/index.ts`, `contracts.ts`, `executor.ts`, and `pipeline.ts` separate the registry from execution. `ToolBatchInput` now takes `calls: ToolCallBlock[]` and returns `ToolBatchResult`.
- `packages/core/tool-executor-ptc/src/index.ts` owns `run_code`, the `tools:sdk` section, and nested dispatch. `packages/core/agent-tool-presentation/src/index.ts` remains as a deprecated compatibility wrapper.
- Built-in presets in `packages/bundle/web-app/presets/ptc.patch.yml` replace the presentation row with `@deepseek-ai/dsh-tool-executor-ptc`.
- `ToolsService.definitions(scope, toolSet)`, `executable`, `register`, guards, and the post-execute waterfall still exist. The PTC SDK cache guard therefore still wraps the same seam; the new executor does not itself freeze that section.

**Bridge**: `src/host/agent-preset.ts` probes `@deepseek-ai/dsh-tool-executor-ptc` and selects the official executor when present, dropping the old `{ mode: 'ptc' }` config. `DISPATCH_PRESET` and `presets/dispatch/agent.cordis.yml` retain the old row for older installations. `test/subagent-model-authorization-ptc.test.ts` mounts the new executor on 0.2.2 and the old ToolRuntime mode otherwise, and speaks both batch and single-call protocols. The focused alpha.3 and exact-rc.5 runs both pass all four real nested-PTC cases.

The three packages that moved out from under `dsh-tools` test resolution are explicit development dependencies where needed: `dsh-ptc-runtime`, `dsh-tool-executor-ptc`, and `dsh-compaction-basic` (the last for request-purpose declarations). None is a new runtime peer requirement of the plugin.

## 2. Plan mode still needs the cache-stable fork (behavioural; retained)

- `packages/plan/plan-mode/src/index.ts` advances the plan projection to stateVersion 4, adds `entered`, uses retained projection handles, and keeps `exit_plan_mode` admitted after the first entry.
- The official service still registers the dynamic `plan:policy` system section and still registers `exit_plan_mode` with `{ when }`. The first admission and every guidance-section transition still change the request prefix. This is an improvement, not a complete replacement for the plugin's cache-stable behavior.

**Decision**: keep `src/entry-plan-mode.ts` and the host guard. The fork already negotiates projection v4/v3, awaits retained handles on new hosts, registers no dynamic system section, and keeps the exit tool unconditional. No switch to the official row is made. `test/plan-mode-fork.test.ts` and `test/kimi-cache-guards.test.ts` pass unchanged in behavior; comments now describe the upstream progressive-admission improvement accurately.

## 3. Pruning and model-switch compaction (behavioural; retained and checked)

- `packages/compaction/compaction-tool-result-pruner/src` has no source delta from rc.3. It still rewrites historical tool results without a provider skip, so it does not replace the plugin fork for Kimi Code and MiniMax Code.
- `packages/compaction/compaction-basic/src/index.ts` adds pre-switch compaction through `agent/request` and a private `compactPressure(agent, header, ...)` path. The existing policy guard observes the proposed header at that method seam, so destination Kimi models still receive the frozen policy; explicit user policies remain first.
- The budget keys, `modelPolicies`, pruning lookup, summary entry point, and waterfall delegation requirements remain present.

**Decision**: keep both the pruner fork and host guards. The full plan/pruner/cache suites pass on alpha.3 and rc.5. No new guard duplicates the upstream model-switch implementation.

## 4. Subagent authorization follows the new Session policy (behavioural; bridged)

- `packages/subagent/tool-subagent/src/model-selection-settings.ts` now records the allowlist during Agent creation; `index.ts` uses retained projection readers and shared preset registrations.
- `model-selection.ts` now limits explicit selection to the parent route when no Session allowlist exists. The previous plugin notice that called this posture unrestricted became false.
- `index.ts` also replaces the old optional-selection wording with “Supply `provider` and `model` together. Omitted values use child defaults …”, so the old rewrite expressions no longer covered the current model-facing text.

**Bridge**: `src/host/subagent-model-authorization.ts` now distinguishes “no Session allowlist” from the host's own parent-route rule, and rewrites both old and new descriptions when the plugin requires an explicit authorized route. The two copies of dispatch R2 carry the same caveat. Upstream still does not provide the plugin's mandatory-pair rule, per-main-model route narrowing, or same-model parent-fork policy, so the custom card and host guard remain.

## 5. Cordis, request purposes, and smaller deltas

- Vendor baseline is Cordis `4.0.6-alpha.2`, Loader `1.0.7-alpha.2`, Schemastery `3.18.6-alpha.2`. Peer unions retain every older clause and add these exact development baselines; all direct DSH development dependencies point at `^0.2.2-alpha.3`.
- Cordis `Fiber.update()` now returns an awaitable and `restart()` works through the context-retained fiber. Production `SearchProviderSwitcher` still settles correctly. Its regression test now observes the public `internal/status` event and matches the Loader entry instead of instrumenting a proxy's own `state` property.
- `GenerateOptions.purpose` is producer-extensible. `src/host/common/llm-compat.ts` forwards purpose strings without requiring every producer's augmentation at the adapter boundary; tests constructing compaction requests import the root type of `dsh-compaction-basic` (there is no `./types` export).
- DSH now ships Russian and other UI locales. That replaces translation of the upstream UI only, not this plugin's own namespaces, so `src/client/locales-ru/` remains intentionally scoped to those namespaces.
- rc.4's UI fixes and rc.5's thinking-rendering change need no plugin bridge. The new optional `apply_patch` rows are not enabled in dispatch. Web readiness, attachment, model badge, composer, and navigation deltas did not require changes to the imported plugin surface.
