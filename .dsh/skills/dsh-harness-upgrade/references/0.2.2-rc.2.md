## 2. Upstream Delta & Code Mode (`code_run`) Bridges

Between `dsh-v0.2.2-rc.1` and `0.2.2-rc.2` (`master` HEAD `e8f7b93a344`), the primary behavioural changes landed in the PTC stack (`@deepseek-ai/dsh-ptc-runtime`, `@deepseek-ai/dsh-ptc-runtime-node`, `@deepseek-ai/dsh-tool-executor-ptc`, `@deepseek-ai/dsh-tools`, `@deepseek-ai/dsh-client-ui-tool`):

1. **Ordered Mixed Text/Image Output (`PtcRunResult.output: PtcOutput[]`)**:
   - Upstream replaced `result.logs: string[]` with `result.output: PtcOutput[]` (`{ type: 'text', text } | { type: 'image', attachment }`).
   - `src/host/codemode/transport.ts` now supports both `result.output` (0.2.2-rc.2+) and legacy `result.logs` (≤0.2.2-rc.1). Adjacent `text` blocks in `result.output` are joined without injecting extra newlines (since `inspect`/`console` blocks carry their own trailing `\n`), and `TransportOutput.logs` is populated from `result.output` when `result.logs` is absent.
2. **Inline Image Projection (`projectContent(exec, result)`)**:
   - `@deepseek-ai/dsh-tools` added `ToolDefinition.projectContent?(exec, result)` in `pipeline.ts`.
   - `createTransportDefinition` implements `projectContent` backed by an `inspections` `WeakMap`: when `result.output` contains `{ type: 'image', attachment }` blocks, `projectContent` projects interleaved text and image `ContentBlock`s in `inspect(...)` order on success, and appends captured pre-failure text/image blocks after the error block on failure (suppressing duplicate `Captured output:` text in `CodeRunFailedError.message`).
3. **`scoped-repl` Default Format & Top-Level `return` Recovery**:
   - `@deepseek-ai/dsh-ptc-runtime-node` switched the default `persistent-in-memory` format from `'repl'` to `'scoped-repl'` (top-level bindings and imports persist across runs, while `let`/`const`/types can be redeclared in later runs).
   - `src/host/codemode/rules.ts` (`buildCodemodeSectionText`) and `src/host/codemode/transport.ts` (`isReplFormat`) now treat `'repl' | 'scoped-repl' | 'script'` as REPL formats so the system prompt emits REPL examples (no top-level `return`).
   - `sanitizeReplTopLevelReturn` in `src/host/codemode/transport.ts` lexically strips a trailing top-level `return <expr>` (wrapping object literals `{ ... }` in `({ ... })`) when running in TypeScript REPL modes, preventing `SyntaxError: Return statement is not allowed here` when models habits from `function-body` leak into REPL runs.
4. **First-Class `PtcImage` Binding + Uninspected Image `deferContext` Fallback**:
   - When the active TypeScript runtime supports `inspect` (`executionInstructions` includes `'inspect'`) and `@deepseek-ai/dsh-llm` exposes `resolveImageAttachmentAccess` (or `read_image` supplies a path), `src/entry-codemode.ts` wraps `read_image` and `cua` attachments in `PtcImageLike` (`Symbol.for('dsh.ptc.image') === true`), which `ptc-runtime-node`'s wire codec reconstructs as `PtcImage` inside the worker.
   - If the program finishes without passing a returned `PtcImage` to `inspect(img)`, `transport.ts` automatically forwards the uninspected image block via `exec.deferContext(createImageContext(...))` so images are never silently lost.
5. **Dual-Snapshot Sub-Call Arguments & Early `trackRun`**:
   - `normalizeSubCallArgsPair` produces independent deep-cloned `dispatched` and `logged` objects so in-place argument mutations inside a tool implementation cannot corrupt `tool/ptc-dispatch` replay logs.
   - `host.trackRun` is registered before `runAuthority` and `escalateSandbox` (and `escalateSandbox` receives `nestedSignal`), ensuring runs waiting on directory creation or user sandbox escalation approval still abort promptly on `sandbox/mode` changes or `executor.reset(agent)`.
6. **Client `CodeRunToolView` Output Flattening**:
   - `flattenCodeRunOutput` in `src/client/codemode/CodeRunToolView.tsx` joins text blocks without doubling newlines when blocks already end with `\n`, matching upstream `tool-call-model.ts`.
7. **Subagent Live Lineage Outside `AgentRegistry` (`b3d4933f39`)**:
   - Upstream removed `ctx.agents.roots()` and `ctx.agents.isOwnedBy()` from `@deepseek-ai/dsh-agent`, moving live subagent tree ownership to `ctx.subagents.rootOf(agent)` and checking `agent.session.header.origin === 'subagent'` in `user-questions` / `action-cards`.
   - `src/entry-plan-mode-pipeline.ts` (`assertLiveRoot`) and `src/host/dispatch-execution-guard.ts` (`isDelegatedCaller` and `hasRunningChildSubagent`) now check `agent.session.header.origin === 'subagent'`, `agent.session.header.parentSession`, and `ctx.subagents.rootOf(agent)` before falling back to `ctx.agents.roots()` / `ctx.agents.isOwnedBy()`.
8. **Delegation Tool Description Wording (`5a75c8b4a5b`)**:
   - `@deepseek-ai/dsh-tool-subagent` updated its optional-selection sentence to `Omit \`provider\`, \`model\`, and \`reasoning_effort\` to use child defaults, falling back to (this backend's route defaults|compatible parent values).` and parameter descriptions to `Child LLM provider id; requires \`model\`.` / `Model id within that provider; requires \`provider\`.`.
   - `rewriteAuthorizedToolDescriptions` in `src/host/subagent-model-authorization.ts` matches both the `0.2.2-rc.1` and `0.2.2-rc.2` phrasings.
