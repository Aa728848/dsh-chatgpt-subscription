# Harness 0.2.1-alpha.5

Previous plugin baseline: **0.2.0-rc.2** (`latest`). Target: **0.2.1-alpha.5**
(`alpha`; npm dist-tags at the time: latest `0.2.0-rc.2`, next `0.2.1-rc.1`,
alpha `0.2.1-alpha.5`). The running CLI and the local checkout both report
`0.2.1-alpha.5`; the checkout HEAD is `1517a4dbca` at tag
`dsh-v0.2.1-alpha.5`. Every harness fact below was read from
`C:\Users\A\Documents\deepseek-harness` at that tag or by `git diff` /
`git show` against `dsh-v0.2.0-rc.2`.

`0.2.1-rc.1` was published to `next` during this round, but neither the local
checkout nor the remote has a `dsh-v0.2.1-rc.1` tag. It is not claimed as a
verified baseline. DSH devDependencies and the new peer clause use the exact
literal `0.2.1-alpha.5`, so a caret cannot silently select that rc release.

The window is large (five alpha releases), so the audit was restricted to the
packages this plugin imports plus the compatibility seams it owns. The changes
that needed action are below. Additive client contracts, first-party account
UI, plugin-market changes, and internal memoization did not require bridges.

## 1. WebServer origin and optional port (type-only at compile time)

- `packages/host/webserver/src/index.ts`: `port` became `number | undefined`,
  `host` widened to concrete IP literals, and TLS support added the standard
  `getOrigin()` API. The plugin passed `port` directly into its Codex local
  image base URL, so the new declaration no longer compiled.
- **Bridge**: `src/host/common/webserver-compat.ts` uses `getOrigin()` when the
  running service provides it and retains the old HTTP fallback, including the
  old `0.0.0.0 -> 127.0.0.1` rule. `src/index.ts` calls this boundary. A legacy
  unbound server now produces an explicit error instead of a URL containing
  `undefined`.
- `test/webserver-compat.test.ts` covers HTTPS/new-origin, both legacy hosts,
  and the unbound failure.

## 2. Idle deadline settlement versus generator cleanup (behavioural)

- Upstream commit `dbb150ff0e` makes `idleWatchdog.next()` reject when its
  deadline abandons a transport read. Its own adapter change also stops
  awaiting the request generator's `return()`, because an async generator
  queues that call behind the abandoned demand.
- The plugin already used the watchdog, but its `finally` awaited
  `iterator.return()`, which reintroduced the hang the upstream fix is meant
  to eliminate.
- **Bridge**: `src/host/common/idle-watchdog.ts` mirrors the upstream fix: it
  still aborts and starts cleanup, but uses a detached, rejection-handled
  drain instead of awaiting it. `test/idle-watchdog.test.ts` proves a stuck
  cleanup cannot hold a failed stream and, only on 0.2.1+, proves a source
  that ignores abort and never settles still ends in `TIMEOUT` promptly. Older
  rooms skip only that new-capability case.

## 3. Reasoning effort order is now semantic (behavioural)

- `packages/llm/llm/src/types.ts` now defines `reasoning.efforts` as least to
  greatest, replacing the old adapter-preferred display order. Commit
  `c56fdb023e` and `packages/session/session-title-llm/src/index.ts` select
  `efforts[0]` for auxiliary title calls.
- **Bridge**: `src/host/common/reasoning-efforts.ts` sorts only a completely
  known ladder; it does not invent an order for unknown provider-specific
  levels. Sorting happens at adapter metadata boundaries, leaving settings UI
  order and default-effort selection unchanged.
  - Kimi: live `['low','high','none']` becomes `['none','low','high']`.
  - MiniMax M3.1: real levels come first; local `default`, whose omission
    means upstream `max`, follows them. The configured default is unchanged.
  - Codex: known live levels use the shared strength order; the fallback
    default is computed before sorting, preserving ordinary request behavior.
- Other static ladders were audited and left alone. Ollama's unknown custom
  levels retain server declaration order because there is no evidence for a
  different strength ordering.

## 4. Exact adapter image targets (new capability, adopted)

- Commit `5658751da0` added `LlmAdapter.imageRequestTarget()` for CUA screenshot
  coordinate mapping. The default reports the original normalized image, which
  is wrong for adapters that actually downscale before serializing.
- **Adopted**: Kimi, Step, MiniMax, and Antigravity now return the same target
  their request mappers use. Small images preserve original dimensions and
  bytes; oversized images use the existing 1024px / 256 KiB policy. The methods
  deliberately omit `override`, so older base classes remain valid.
- Claude was not given a fabricated implementation: its edge limit depends on
  the number of images in the whole request, while the new API receives only
  one image and cannot reproduce that decision.
- The old attachment closure also exposed that `ImageRequestPolicy` requires
  `maxPixels`. The shared and Antigravity target builders now carry it using
  the same unrounded-aspect-ratio formula Claude already used; newer stores
  continue to consume `width` / `height` / `maxBytes`. This changes no new-wire
  behavior and restores old-store compatibility.

## 5. Tool args and PTC generation changes

- The new lazy tool-argument view is useful now: `CodexImageToolView` reads a
  preparing prompt through `args.text('prompt')`, with the previous `argsRaw`
  and `call.argsRaw` fallbacks for older shapes. This view is shared by Codex
  and Antigravity image generation.
- `dsh-tools` removed mixed `both` presentation and removed the old invariant
  exports; this plugin uses neither. Nested PTC presentation metadata and the
  `workingDirectory` requirement were reviewed.
- The first PTC failures were in the **test fixture, not production policy**.
  The new transport requires `workingDirectory` and uses `agent.ctx` to retain
  and release owner state. `test/subagent-model-authorization-ptc.test.ts` now
  supplies a structural directory service and a real agent Context. All four
  authorization tests pass on 0.2.1 and rc.2; the production guard is unchanged.
- Older Harness types also lack `toolHistory`, `deferLoading`, and tool-update
  blocks used by the existing GLM routes. `src/host/common/llm-compat.ts` now
  carries those fields at its existing compatibility boundary without changing
  runtime behavior or the outbound block vocabulary. Existing GLM rejection
  tests cover all three cases.

## 6. Dependency closure

- All 15 DSH peer unions gained exact `0.2.1-alpha.5`; all 15 devDependencies
  use the same literal. `package-lock.json` and `pnpm-lock.yaml` contain no
  `0.2.1-rc.1` entries.
- The tag's vendor versions were alpha, but the simultaneously published stable
  Cordis packages are accepted by the alpha.5 DSH peer ranges. Using alpha at
  the root while npm selected stable transitive plugins produced real peer
  conflicts. The consistent closure therefore uses stable
  `cordis@4.0.5`, `cordis-plugin-loader@1.0.6`, and `schemastery@3.18.5`.
  The older peer ranges remain in place, and `npm ci --dry-run` is clean with
  no ERESOLVE override warnings.
- `pnpm-workspace.yaml` covers both alpha and stable vendor releases and the
  new `dsh-fs` / `dsh-working-directory` closure entries.

## 7. Deliberately not adopted in this round

- `conversation.input.model.label` is a real new extension point, but replacing
  nine composer quota badges needs a separate old/new dual-track design,
  duplicate-render avoidance, and a new polling model. The current badges stay.
- `AccountNoticeStack` is first-party account reward/billing presentation, not a
  general plugin notification service. `shell.quota-notice` was not claimed as
  a drop-in replacement either.
- `ConfigureCall` is used by the upstream title service; the plugin has no
  auxiliary `prepareCall` call site of its own and gained no wrapper.
- `toolUpdate`, nested PTC `presentationMeta`, and the official image factory
  remain separate follow-up candidates, not claimed benefits.
- The test-only Claude OAuth fix chooses the next actually bindable port instead
  of assuming `freePort + 1`; direct probing had shown `53692` bindable and
  `53693` dynamically reserved with `EACCES`. Production OAuth code is unchanged.
