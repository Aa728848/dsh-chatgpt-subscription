(peer union, devDependencies, both lockfiles) and the verification below.

## 1. Imported packages with a source delta (all checked, none bridged)

- **`ui-model-selection`** — `directory.ts` / `service.ts`:
  `ModelDirectory`'s constructor gains a **required** `isBlank: () => boolean`
  and an optional `track?: TrackProductEvent` (desktop model-switch analytics).
  The plugin imports `ModelDirectoryState` **type-only** and never constructs
  the directory, so nothing moves; the forced typecheck is clean. The type
  itself is unchanged at both tags. The monorepo manifest adds
  `@deepseek-ai/dsh-client-product-analytics` as a `workspace:*` dependency,
  but the **published** package.json strips it (verified in
  `node_modules/.../package.json`: no `dependencies` carrying it), so our
  install closure does not grow and no peer clause is needed for it.
- **`ui-conversation`** — input machine / facade / hub / submission-analytics
  internals. The slot contract this plugin registers into is **byte-identical**:
  `'conversation.input.right': { kind: 'list', scope: 'session' }` at
  `apply.ts:429` and `contract/slots.ts:203` at both tags, and
  `git diff <old>..<new> -- packages/client/ui-slots/src
  packages/client/ui-chat/src/client/contract` is **empty** — the
  `tool.call.toolview` stage union (the rc.1 seam) did not move either.
- **`ui-tool`** — `ToolRow.tsx` drops the `active` prop from `TextShimmer`
  (first-party internal); the plugin imports `dsh-client-ui-tool/client` as
  `import type {}` for the service merge only.
- **`ui-chat`** — transcript-view default flips `standard` → `detailed` for
  non-Desktop clients (`chat-settings.ts`), `Config.transcriptView` widens to
  `ChatSettings['transcriptView']` (optional/nullable), `forkAt` gains
  analytics. The plugin reads none of these.
- **`agent-loop`** — `agent.ts` adds `ToolCallRecovery` (from `dsh-session`):
  on a step failure, pending tool results are recorded before the step closes.
  This rewrites **session-event** bookkeeping inside the harness; the request
  vocabulary the plugin normalizes at its adapter boundary lives in
  `dsh-llm`, whose source is unchanged (version-only bump), so the
  conversation-model seam (`src/host/common/llm-compat.ts`) is untouched.
- **`api/session-controller` client** — `ISessions.fork` gains an optional
  `onCreated?: (childId) => void`. Additive; the plugin does not call `fork`.
- **`api/remotes` client** — adds `productAnalyticsRemote` to the assembly.
  The plugin never touches `ctx.remote` (grep: 0 hits).
